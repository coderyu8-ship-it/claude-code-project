# Clarity → カートページ 週次分析ドキュメント作成 手順書（Claude in Chrome 用）

日次記入（`clarity-daily-runbook.md`）と同じく、Claude デスクトップアプリ＋Claude in Chrome で、
ログイン済みの Chrome から Clarity を読み取る。クラウドの Routine では Clarity にログインできないため使わない。

## 対象

| 項目 | 値 |
| --- | --- |
| Clarity プロジェクト | 田丸屋_通常LP |
| 対象 URL | `https://tamaruya-udon.jp/cart`（閲覧済み URL・完全一致） |
| デバイス | スマートフォン（モバイル）固定 |
| 表示 | タップ（クリック）ヒートマップ |
| 集計単位 | 木曜〜水曜の 7 日間。初週は 2026/10/01〜10/07 |
| 保存先 | Google ドライブ https://drive.google.com/drive/folders/1WbLPoumYJjp2VXaQWRWqvdeKOK-M4lpY |
| ファイル名 | `カートページ週次分析_YYYY-MM-DD〜MM-DD`（例: `カートページ週次分析_2026-10-01〜10-07`） |

## 実行スケジュール

- 毎週木曜 10:00（JST）に実行する。PC が使えなかった場合は、次に PC を開いたタイミングで 1 回実行する。
- 2026/10/01 以降の完了した週のうち、保存先フォルダに同名ファイルがない週を古い順に作る。
  実行されなかった週があっても次の実行で追いつく。同名ファイルがある週は飛ばすので二重作成にはならない。

## 毎週実行させる指示文（デスクトップアプリのスケジュールに登録）

```
Clarity のカートページの数値を読み取り、週次分析を Google ドキュメントで作成してください。読み取りとドキュメント作成以外の操作（Clarity の設定変更・削除・共有、既存ファイルの編集・削除）は一切しないこと。

■ 対象週の決め方
1. Google ドライブのフォルダ https://drive.google.com/drive/folders/1WbLPoumYJjp2VXaQWRWqvdeKOK-M4lpY を開く。
2. 2026/10/01（木）から始まる木曜〜水曜の 7 日間を 1 週とし、実行日（日本時間）より前に水曜が終わっている週をすべて候補にする。実行日を含む週は対象外。
3. 候補の各週について、フォルダに「カートページ週次分析_YYYY-MM-DD〜MM-DD」のファイルがあるか確認する。
   - ある週: 作成済みとみなして飛ばす。
   - ない週: 「対象週」とする。
4. 対象週が 1 つもなければ、何もせずに「実行済み（作成対象なし）」とだけ報告して終了する。
5. 対象週を古い順に 1 週ずつ、以下の「1 週分の処理」で作成する。

■ 1 週分の処理（対象週 = W、前週 = W-1）
6. https://clarity.microsoft.com を開き、プロジェクト「田丸屋_通常LP」を選ぶ。
7. 上部メニュー「ヒートマップ」を開き、次を設定する。
   - 期間: W の木曜 00:00 〜 水曜 23:59（カスタム期間）
   - 「閲覧済み URL」フィルター: 条件「完全一致」、値 https://tamaruya-udon.jp/cart
   - デバイス切替（左上の 3 つのアイコン）: 右端のスマートフォンのアイコン
   - 表示切替: 「タップ」
   いずれかを設定できない場合は、その週は作成せずに止まって報告する。
8. ヒートマップ下部の「◯ ページ ビュー」「◯ タップ」の数値を読む → PV、TAP とする。
   PV が 0 なら、その週は「データなし」とだけ書いたドキュメントを作り、次の週へ進む。
9. 左側パネル「クリック数の多い順にランキング」を、パネルを下までスクロールして全要素読む。
   各要素の 順位・要素名・クリック数・割合 を画面どおりに控える。計算はしない。
   要素の総数（「◯ 個の要素」）も控える。
10. 控えた値の確認: 全要素のクリック数の合計が TAP と一致するか。合わなければ、その旨を「データの注意点」に書いたうえで続ける。
11. 前週 W-1 のドキュメントがフォルダにあれば開き、「2. 主要指標」の今週列の値を前週値として使う。なければ前週列は「－」。
12. 以下の構成で分析を書く。要素は次のグループに分類して集計する。
   - 購入へ進む: 「購入手続きへ」
   - 配送日時の入力: カレンダー（react-calendar / react-date-picker）、時間選択（timeSelect）
   - 離脱方向: ショッピングガイド、ハンバーガーメニュー、買い物を続ける、ロゴ、ヘッダーのカートアイコン
   - のし・名入れ: 熨斗を追加する、説明文付近、備考欄
   - 数量・削除: 数量の±、削除
   - その他: 上記以外

   構成（見出しはこのとおり）:
   1. サマリー（3〜4 行。最重要の変化と、その週の仮説）
   2. 主要指標（表: 指標／今週／前週／増減）
      - ページビュー、タップ数、購入手続きへ クリック、購入手続きへ ÷ PV（上限値と明記）、離脱方向クリック合計、配送日時の入力クリック合計
   3. タップランキング（表: 順位／要素／クリック／割合／グループ）。上位 10 件まで。残りは件数のみ
   4. 現状分析（表: 所見／根拠／確信度 高・中・低）
   5. 改善案（表: 優先／内容／理由／手間／状態）。前週ドキュメントの改善案の「状態」を引き継ぎ、変化がなければそのまま
   6. 次週までのアクション
   7. データの注意点（PV が 100 未満なら「母数が少なく仮説扱い」と必ず書く。クリック数はセッション数ではないことも書く）

   書き方のルール:
   - 数値は画面で読んだ値だけを使う。推測で埋めない。読めなかった値は「読み取り不可」と書く。
   - PV が 100 未満の週は、増減の大小で断定しない。確信度は最高でも「中」。
   - 「購入手続きへ ÷ PV」は同一ユーザーの再クリックを含むため上限値と書く。
13. Google ドライブの上記フォルダに、新しい Google ドキュメントを「カートページ週次分析_YYYY-MM-DD〜MM-DD」の名前で作成し、12 の内容を書き込む。
14. 作成後にドキュメントを開き直し、見出し 1〜7 がそろっていること、主要指標の PV・タップ数が手順 8 の値と一致することを確認する。

■ 報告（以下に限る）
15. 作成したドキュメントの名前とリンク、各週の PV・タップ数・購入手続きへクリック数、および次の異常があればその内容のみを報告する。
   - ログイン切れ
   - 手順 7 の設定ができなかった週
   - 手順 10 の合計が合わなかった週
   - 読み取れなかった値
```

## 運用ルール

- 最初の 2 週は、Clarity 画面とドキュメントの数値を人が突き合わせる。
- 改善を実施したら、その週のドキュメントの改善案「状態」を人が「実施済み（M/D）」に書き換える。翌週以降はそれが引き継がれる。
- Clarity の UI が変わって手順が合わなくなったら、この手順書を更新する。
