# Meta広告バナー作成

一言の依頼から、企画3案→推奨1案→画像→サイズ展開まで進める。途中で確認を挟むのは「推奨案の承認」の1回だけにする。

## 0. 前提ファイルを読む

1. `brands/<brand>/brand.md` を読む。ブランドの指定がなければ `brands/` 配下が1つならそれを使い、複数あれば聞く。
2. brand.md の「勝ちパターン」「NG」「要確認の訴求」を、以降すべての判断基準にする。
3. 最新の実績レポートがあれば Drive で検索して読む（例：`fullText contains '<ブランド名>' and fullText contains 'バナー分析'`）。brand.md より新しければ、そちらを優先する。

## 1. 調べる（CLAUDE.md の常時ルール）

作る前に Web 検索で、次のことを確認する。
- 時期の外部要因：季節行事・商戦（お歳暮、年末年始、母の日など）、気温
- LP の現状：価格・キャンペーン・表記の変更（WebFetch で遷移先LPを確認）

## 2. 企画3案を出す

各案に次の項目を書く。
- 狙い（誰の、どんな気持ちに刺さるか）
- 写真（brand.md の勝つ写真の条件に合うもの。素材ファイル名を指定する）
- メインコピー（全角15字前後）／サブコピー（全角30字以内）
- 根拠（過去の実績の数値、または調べた外部要因）
- 検証方法（何と比べて、何を見て判断するか）

**推奨案を必ず1つ選び、理由を書く。** 実績がある勝ちパターンから1要素だけ変える案を優先する（変える要素が多いと、何が効いたのか判別できない）。

ユーザーの承認を得てから、次に進む。

## 3. 画像を作る（Canva）

- 使うツール：`mcp__Canva__generate-design` または `create-design` ＋ `edit-design`、素材は `upload-asset-from-url` / `create-upload-url`、書き出しは `export-design`
- **写真**：原則として実写の商品写真を使う。AI で料理写真を生成しない（食品の誤認表示と信頼性低下のリスク）。実写がない場合だけ生成を使い、その旨をユーザーに伝える
- **ロゴ**：必ず正規のロゴ画像を貼る。AI に描かせない（過去に創業年の誤記が5本出た）
- **文字**：画像の20%程度以内に抑える。写真が主役
- サイズ：1080×1080（1:1）→ 1080×1350（4:5）→ 1080×1920（9:16）の順で展開。9:16 は上下14%程度に文字やロゴを置かない（UIに隠れるため）

## 4. 出す前のチェック（全部確認してから渡す）

- [ ] ロゴの創業年が **ESTD.1582**（brand.md に書かれた正しい値）になっている
- [ ] 価格・送料・熨斗の表記が、当日のLPと一致している
- [ ] 「要確認の訴求」を使っていない。使う場合は根拠の注記がある
- [ ] NG の写真・表現を使っていない
- [ ] 誤字脱字、商品名の表記（LP表記に合わせる）
- [ ] スマホ表示を想定して、コピーが読める大きさか

## 5. 渡し方

- Canva の編集リンクと、PNG の書き出しファイルの両方を渡す
- ファイル名：`<ブランド>_<YYYYMMDD>_<案名>_<比率>.png`（例：`tamaruya_20261028_curry-hie_1x1.png`）
- 入稿メモを添える：広告セット、比較対象のバナー、判断基準（例：「ver23 と同じ広告セットで7日配信。CPA(v2) が ver23 の110%以内ならローテーション入り」）

## 6. 終わったら更新する

- 新しく素材ファイルを特定したら、brand.md の「商品写真の対応表」に追記する
- 実績が出たら、brand.md の「勝ちパターン」を更新する
