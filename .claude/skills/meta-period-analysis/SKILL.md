# Meta広告 期間別（1週・2週・3週・1ヶ月）分析と改善案

お手本：「20261102時点_Meta広告 期間別（1週・2週・3週・1ヶ月）分析と改善案」（田丸屋、Google ドキュメント ID `1LhbWWejF67MHcy1s7Rb_bctGJ_0LF6pIgTQjTIer00M`）。
構成・粒度・文体はこれに合わせる。迷ったら読んで確認する。

## 0. 前提

1. `brands/<brand>/brand.md` を読む。指定がなく `brands/` 配下が1つならそれを使う。
2. **基準日**＝集計の最終日。指定がなければ「昨日」。作成日＝今日。
3. 対象キャンペーン／広告セット名は、ユーザー指定 → 前回の同名ドキュメント（Drive で `name contains '期間別'` を検索）→ brand.md の順で決める。

## 1. 数字を集める（広告マネージャの表示値）

次の4期間、すべて基準日まで：
- 1週間（基準日−6日〜）／2週間（−13日〜）／3週間（−20日〜）／1ヶ月（約30日前〜）

取得する指標（列名は広告マネージャの表示どおり）：商品購入v2、v4、商品詳細v2_1、商品詳細v2_2、消化金額。
粒度は **広告セット全体** と **広告ごと（状態：配信中／オフ も）** の2つ。

**鮮度チェック（最初に必ず行う）**：使うデータの最終日（シート1行目の「開始〜終了」の終了日）が、今日から3日以内（今日−3日以降）でなければ、ドキュメントを作らずに止める。最新シート名・データ最終日を伝え、「データを更新するか、この日付で作るか」次の指示を求める。

入手方法（上から優先）：
0. **田丸屋の標準データ**：Drive フォルダ `1l0rSsP9yG-NNr8KQ7QzBUYoju-Pvl9PO` の最新「YYYYMMDD時点_Meta広告バナー分析」スプレッドシート。タブ「1週間」「2週間」「3週間」「1ヶ月」に広告別の値（広告費・v2(カート)・v4(決済入力後)・配信状態）があり、広告セット全体はその合計で出す。期間はシート1行目の「取得: … / 開始〜終了」に従う（通常は基準日の前日まで）。このシートの v2 はカート、v4 は決済入力後で、商品詳細v2_1／v2_2 はない。ドキュメント冒頭に定義を明記する
1. ユーザーが貼ったスクリーンショット・CSV
2. Drive／スプレッドシートの同期データ（GAS 連携シートがあれば）
3. どちらもなければ、Claude in Chrome 用の取得手順を出して止まる（数字を推測で埋めない）

## 2. 計算

- 週ごとの数字＝長い期間の合計−短い期間の合計（例：3週目＝3週間−2週間）。1ヶ月−3週間は日数が7日でないので「（9日）」のように日数を明記する。
- 1件あたり＝消化金額÷v2。「約¥3,450」のように百円〜十円単位に丸める。最良週に「（最良）」、直近で上がったら「（悪化）」を付ける。
- 日予算と実際の1日平均消化を比較する。
- 主力広告（消化が最も多い、または直近まで主力だった広告）は週ごとの v2／消化／1件あたりを出す。

## 3. 調べる（CLAUDE.md の常時ルール）

外部要因（気温・季節行事・お歳暮など商戦・Meta の仕様変更）を Web 検索で確認し、改善案に効くものだけ反映する。推測は「（推測）」と書く。

## 4. ドキュメント構成

タイトル：`【即時作成】<基準日の翌日 YYYYMMDD>時点_Meta広告 期間別（1週・2週・3週・1ヶ月）分析と改善案`
（お手本は基準日11/01・作成日11/02で「20261102時点」）

本文：
- 見出し：`Meta広告 期間別分析と改善案（<ブランド名>）`
- 作成日／集計期間（4期間を日付付きで列挙、「いずれも<基準日>まで」）／対象（キャンペーン・広告セット）／方法（「広告マネージャの表示値。週ごとの数字は、長い期間の合計から短い期間の合計を引いて算出」）／関連（同日の他の分析ドキュメントがあれば名前）
1. **期間ごとの累計（広告セット全体）**：表（期間｜商品購入v2｜v4｜商品詳細v2_1｜商品詳細v2_2｜消化金額）
2. **週ごとの推移（広告セット全体）**：表（週｜商品購入v2｜v4｜消化金額｜v2の1件あたり）＋所見を箇条書き3つ程度（1件あたりの傾向、v4の動き、日予算と実消化の差）
3. **広告ごとの推移**
   - 主力広告：週ごとの表（週｜v2｜消化金額｜1件あたり）＋所見（疲弊の判断は「（推測）」付き）
   - その他：表（広告｜状態｜1週間｜2週間｜3週間｜1ヶ月｜所見）。セルは「v2件数／¥消化」。配信のない期間は「—」
4. **改善案**：5〜6項目。各項目は「何をするか」を1文目に、次に根拠と判断基準（例：「消化¥10,000まで見て、1件あたり¥2,500以下なら主力候補」）。brand.md の NG（誤ロゴ等）に触れる素材があれば指摘する。
- 末尾：「※本分析の時点で、広告マネージャの設定は変更していない。」

## 5. ルール

- 広告マネージャの設定は変更しない（分析と提案のみ）。
- 数字は表示値をそのまま使い、計算値は「約」を付ける。件数が少ない広告は「判断保留」と書く。
- 文体：常体、短文、です・ます不要。カタカナ専門語は最小限。
- Drive に作るときは text/markdown で作成し、表の見出し行に ** を付けない（変換時に記号がそのまま残る）。
- 完成したドキュメントの保存先：Drive フォルダ `1l0rSsP9yG-NNr8KQ7QzBUYoju-Pvl9PO`（データ元と同じフォルダ）。
- 作成後、ドキュメントの URL と、改善案のうち最優先の1つを一言で返す。
