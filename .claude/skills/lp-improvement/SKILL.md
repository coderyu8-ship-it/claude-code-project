# LP改善案（Clarity・KPIシート分析）

一言の依頼から、データ収集 → 前回の案の対応状況の確認 → 改善案 → Googleドキュメントへの保存までを、途中で確認を挟まずに一気に行う。
期間の指定がなければ「前回の改善案の作成日の翌日〜数値シートの最新日」を今回の期間にし、前月と比べる。

## 0. 固定情報

- 対象LP：https://mizusawaudontamaruya.jp/lp/
- ECサイト：https://tamaruya-udon.jp/（配送ポリシー：/policies/shipping-policy）
- 数値管理シート：田丸屋様_Meta広告の数値管理（ID `1IWlkOrVyqNjxx_WXbFP_N9HuceOdEkRiDDPRsIgshgo`）
  - 「各KPI」：月別の目標と実績
  - 「Meta広告の数値」：日別の数値。**メモ列（W列）に施策の実施日と計測の注意が書いてある。必ず読む**
  - 「LPリンクの遷移数」：商品リンクごとのクリック数（月合計の行と日別の行）
  - 「LPヒートマップ」：スクロール到達率（Clarity、スマホのみ）
- 保存先フォルダ：Drive `1xZuY2bPAoLL0dKbdfIqEz1yUl7Ijx0b7`（https://drive.google.com/drive/folders/1xZuY2bPAoLL0dKbdfIqEz1yUl7Ijx0b7）
- 前提方針（ユーザーが変えない限り固定）：**ボタンは増やさない／LPは1本で考える（別LPは作らない）**

## 1. データを集める（全部読む）

1. 前回の改善案：Drive で `title contains 'LP改善案'` を検索し、いちばん新しいものを読む。
2. 数値管理シートの4シート。行の位置は月ごとに変わるので、A列の「◯月合計」と日付から探す。
3. LP本文：WebFetch で取得する。各セクション・価格・送料の表記・ボタン・お歳暮などの季節表記・数値の主張を確認する。
4. ECの配送ポリシー（送料・発送日数）。
5. 関連レポート：Drive で、最新の週次分析レポート・バナー分析レポート・カートページ週次分析・「LPとECサイトの表記比較」を検索し、前回以降のものを読む。
6. Clarity：管理画面は直接見られない。シートに転記された値と、Drive にあるClarityのCSV（`title contains 'Clarity'`）を使う。ユーザーが数字を貼ってきたら、それを優先する。
7. 外部要因（CLAUDE.md のルール）：季節の行事・商戦（お中元・お歳暮・お年賀など）の時期を WebSearch で調べ、出典を付ける。

## 2. 分析の観点

- **前回の案の対応状況**：各案が、今のLPに反映されているか（対応済み／未対応／不明）。
- **施策の前後比較**：メモ列にある施策の日付で期間を区切って比べる。件数が少ないときは「まだ判断できない」と書く。
- **ページ構成が変わった日以降のスクロール％**：ページの長さが変わると、位置（％）は前と比べられない。このことを明記する。
- **購入までのどこで落ちているか**：クリック率 → 購入手続きへの移行率（v2÷クリック） → 完了率（v4÷v2）の順に、月別の推移で見る。
- **計測の異常**：実績0件で、メモに「表示なし（0として記入）」とあるものは、実績ではなく計測の問題として扱う。
- 推測には必ず「（推測）」と書く。二次情報は「二次情報」と書く。

## 4. 保存と報告

1. scratchpad に Markdown を書き、`mcp__Google_Drive__create_file`（contentMimeType `text/markdown`、parentId は上の保存先フォルダ）で Google ドキュメントとして保存する。
2. ユーザーには、ドキュメントのリンク、要点3つ、推奨案、確認してほしいこと（取れなかったデータ・クライアントに聞く事項）だけを返す。
